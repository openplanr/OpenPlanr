# Operating Board Agentic Execution — Protocol v1.3

> Generated by Doc-Gen Agent on 2026-07-31
> Spec: `.planr/specs/SPEC-004-operating-board-agentic-execution/` · ADR: `docs/adrs/ADR-010-operating-board-agentic-execution.md`
> Protocol reference: `docs/protocol/operating-board.md` § "Protocol v1.3 agentic execution"

## What this feature is

The Operating Board is the evidence-to-decision control plane introduced under
Protocol v1.2 (SPEC-002/ADR-006): event sourcing, a write-ahead journal,
deterministic consolidation and scoring, digest-bound route previews, and
human governance. That engine was correct but its execution model was
inverted — advisory lenses ("CEO", "CTO", "CPO", "CMO", "COO", "Chair") had to
run with **enforced empty-tool isolation**, which forced the engine to
pre-load the whole repository into a JSON "role pack" and hand it to a
tool-capable coding agent that was then asked to reason without looking at
anything. A production role pack for the CTO lens measured 405,820 bytes
against a declared 393,216-byte budget that was never actually enforced in
code, and 274,778 of those bytes were duplicated source text.

Protocol v1.3 (this feature, SPEC-004) keeps every SPEC-002 governance
guarantee and replaces only the execution model:

```text
charter + evidence INDEX (paths, revisions, signals — no bodies)
                         ↓
   native role agents investigate with bounded read-only tools
                         ↓
        findings citing exact paths, lines, and revisions
                         ↓
       engine RESOLVES and SNAPSHOTS every citation, or rejects
                         ↓
          deterministic consolidation and scoring (unchanged)
                         ↓
              DEV | OWNER | AGENT routes (unchanged)
```

Auditability moves from "trust what was pre-loaded" to "verify every citation
after the fact" — a fabricated citation now fails closed, where previously a
model could confabulate over a dump and nothing would catch it.

## Amendment record against SPEC-002

SPEC-002 states normatively that "native advisors require enforced empty-tool
isolation; otherwise execution uses a structured provider path or fails
closed." SPEC-004's own conformance suite would fail any implementation that
grants advisory agents read tools under that clause — so the clause itself is
the defect, and this feature records an explicit amendment rather than
letting the implementation quietly drift from a contract it still claimed.

| SPEC-002 clause | SPEC-004 replacement |
|---|---|
| Advisors run with enforced *empty-tool* isolation | Advisors run with enforced *read-only, path-confined* tool isolation |
| Honeytoken proves advisors cannot access files | Honeytoken proves advisors cannot **write**, **execute**, reach the **network**, read the **environment**, or escape **declared roots** |
| Role pack embeds role-filtered evidence bodies | Mission packet carries an evidence **index**; bodies are read by the agent on demand |
| Findings cite evidence IDs present in the input | Findings cite **repository paths, line ranges, revisions, and planr artifacts**, resolved and snapshotted by the engine |
| — | **New:** unresolvable citations reject the finding (release-blocking) |

Everything else SPEC-002 established remains binding and unchanged: event
sourcing, the write-ahead journal, deterministic consolidation and scoring,
accept ≠ apply, digest-bound previews, byte-exact rollback, typed outcomes,
R1 (nothing may invoke SHIP), evidence framed as untrusted data, and the
post-output secret scan. Determinism is unaffected — reduction stays
deterministic code, so identical validated results reduce byte-identically
regardless of dispatch order. See `docs/adrs/ADR-010-operating-board-agentic-execution.md`
for the full decision record, including rejected alternatives.

Protocol increments to **1.3.0 additively**. Every `schemas/v1.3.0/*` contract
is registered in `lib/protocol/contracts.mjs` alongside — never in place of —
its `schemas/v1.2.0/*` counterpart, and v1.2 readers keep validating v1.2
artifacts unchanged.

## Per-module reference

### `lib/operate/mission-packet.mjs` — FR1

`createOperatingMissionPacket(roleId, evidenceItems, options)` assembles a
digest-bound `operating-mission-packet` from the role's registry-derived
brief (mandate/authority/output, reused from `advisor-brief.mjs`) plus a
caller-supplied evidence-index array filtered to the role's
`permittedEvidenceKinds` and sorted deterministically by `(source, path)`.
The packet is measured with `Buffer.byteLength(canonicalizeJson(unsigned))`
against the role's `budgets.maxInputBytes`; if it would exceed that budget
the function throws `E_OPERATE_MISSION_PACKET_BUDGET` naming the role — it
never truncates the evidence index to fit. The packet is validated against
`operating-mission-packet@1.3.0` before it is returned and stamped with a
`packetDigest` (`sha256Jcs`). The module also exports
`createMissionToolGrant(roots)`, the single source of the seven-capability
bounded read-only grant (`file-read`, `glob`, `content-search`, `git-log`,
`git-show`, `git-diff`, `git-blame`) shared by the mission packet, the
adapter handoff, and the generated lens agents.

### `lib/operate/citation.mjs` — FR3 (release-blocking, the audit mechanism)

Pure, deterministic module with three exports:

- `validateOperatingCitation(citation)` — rejects a citation missing
  `pinnedRevision` before any further check, then validates the shape
  against the canonical `operating-citation@1.3.0` contract via
  `assertProtocolArtifact` (no locally embedded schema — see
  [verification.md](./verification.md) for why that distinction matters).
- `resolveOperatingCitation(citation, facts)` — takes booleans the caller
  (the OpenPlanr citation resolver) computes against live repo/git/planr
  state (`pathExistsAtRevision`, `lineRangeInBounds`, `revisionIsCurrent`,
  `artifactExists`) and returns either `{ outcome: 'resolved', evidenceId,
  snapshotDigest }` or `{ outcome: 'rejected', reason, gapId }`. Both IDs are
  `sha256Jcs` over the citation plus the facts, so identical inputs always
  reproduce identical outputs. Rejection reason follows a fixed precedence:
  path existence, then line range, then revision freshness, then artifact
  existence — the first failing fact wins.
- `buildUnresolvableCitationGap(citation, rejection, context)` — builds an
  `operating-data-gap@1.3.0` record with `category: "unresolvable-citation"`
  for the existing generic `gap.open` event; no new event discriminator was
  introduced.

This module never touches the filesystem, network, or git — it is the
contract the OpenPlanr citation resolver must satisfy, not a reimplementation
of it.

### `lib/operate/adapter-handoff.mjs` — v1.3 branch (FR2)

`createOperatingAdapterHandoff()` and its helpers are protocol-version aware.
For `protocolVersion: '1.2.0'` the module emits the original
`rolePackPointer` / `isolation: 'enforced-empty-tools'` dispatch shape
byte-for-byte. For `'1.3.0'`, `missionDispatch()` emits
`missionPacketPointer`, `declaredRoots`, a `toolGrant` (from
`createMissionToolGrant`), and an `isolation` value chosen by
`roleDispatchMode(roleId) === 'mission' && adapterEnforcesBoundedReadOnly(runtime)`:
`enforced-read-only-bounded` when both hold, `fail-closed-structured-provider`
otherwise. `adapterEnforcesBoundedReadOnly()` derives its answer from the
adapter's existing v1.2 `capabilities.toolIsolation === 'enforced'` field in
`registry/adapters.json` — **see the drift note below**, this is a
disclosed, QA-reviewed deviation from what US-002/T-002 originally specified.

### `lib/operate/records-migration.mjs` — FR5

Pure mapping between the SPEC-002 directory-per-digest-prefix
`operating-record` layout and the v1.3 single-file `.state/records.jsonl`
layout:

- `migrateRecordsDirectoryToJsonl(legacyRecords, options)` — reshapes each
  record's *container* into an `operating-records-log-entry@1.3.0` line
  (same field set, digest-sorted, one JSON object per line) and returns an
  `operating-migration-record@1.3.0` with `sourceKind: 'protocol-upgrade'`,
  `sourceLayout: 'directory-per-digest-prefix'`, `targetLayout:
  'records-jsonl'`, and `recordCount`/`eventCount` before/after pairs that
  are identical by construction (this migration never touches content, so
  losslessness is structural, not just tested).
- `reconstructDirectoryLayoutFromJsonl(lines)` — exact inverse, used only to
  prove reversibility; the readable layout never regresses to per-file
  storage in production.
- `flattenReconstructedLayout(layout)` — convenience flattening for
  reversibility assertions.

### `lib/operate/cadence.mjs` — FR8

`computeNextDueDate(cadence, lastRunAt, now)` is a pure function over exactly
three string inputs, with no `Date.now()` call anywhere in the module:
`manual` always returns `nextDueAt: null`; `weekly` adds 7 days to
`lastRunAt` (or returns `now` on a first run); `monthly` adds one calendar
month, clamping to the last day of a shorter target month. The returned
object is validated against `operating-cadence-status@1.3.0` before it is
returned. `assertCadenceCannotMutate()` is a documented no-op export whose
only purpose is to be a reviewable anchor confirming the function's
signature has no argument through which a caller could pass an action, a
route, or a PLAN/SHIP request.

### `lib/operate/decision-brief-artifact.mjs` — FR7

`createOperatingDecisionBriefArtifact(brief, decision)` renders a brief
(title/question/evidence/options/what-it-blocks) and an optional owner
decision into canonical Markdown, then a minimal dependency-free HTML
fragment (a small hand-rolled Markdown→HTML renderer supporting headings,
lists, paragraphs, and inline `**bold**`/`*italic*`/`` `code` `` — no links
are ever emitted), wraps it in a single `{ id, kind: 'html', title, sha256,
html, viewport, colorScheme }` artifact item, and hands it to
`createArtifactEnvelope()` from the existing SPEC-001 artifact pipeline
(`lib/artifact/envelope.mjs`). `assertOffline()` scans the generated HTML for
any `http://`/`https://` occurrence and fails closed before an envelope is
ever produced — this is enforced in the module itself, not just in tests.
Rendering the same brief/decision twice produces a byte-identical envelope.

### Generated assets — `scripts/generate-operating-assets.mjs` (FR4, FR8)

Extended (not replaced) for this feature. Two new renderers were folded into
the same `renderOperatingAssets()` object that already drives the
`--check`/`E_OPERATING_ASSET_DRIFT` machinery for the pre-existing five
targets:

- `renderOperatingLensAgentAssets(roles)` → one `agents/operating/<role-id>.md`
  per role whose (in-memory-derived) `dispatchMode` is `"mission"`, from
  `templates/runtime/operating-lens-agent.md.tpl`, mirroring the delivery
  agent frontmatter shape (`name`, `description`, `tools`, `model`). The
  fixed capability→tool mapping (`file-read → Read`, `glob → Glob`,
  `content-search → Grep`, `git-log/show/diff/blame →
  Bash(git <verb>:*)`) lives in `TOOL_GRANT_TO_CLAUDE_TOOL` and never emits
  `Edit`, `Write`, or an unscoped `Bash(*)`. The generator throws
  `E_OPERATING_LENS_AGENT_PATH_COLLISION` if a generated path would ever
  collide with one of the nine canonical delivery agents; lens agents live
  under `agents/operating/` specifically so that collision is structurally
  impossible.
- `renderOperatingLensAgentDocs(roles)` → `docs/generated/operating-lens-agents.md`,
  one row per lens (or an explicit "pack-mode, no native agent generated"
  row rather than a silent omission).
- `renderOperatingCadenceDocs()` → `docs/generated/operating-cadence.md`, a
  static summary of the cadence contract (not a live dashboard).

The six generated lens agents currently on disk:
`agents/operating/{strategy-finance,technology-risk,product-activation,growth-market,operations-customer,chair}.md`.
Each carries `tools: Read, Glob, Grep, Bash(git log:*), Bash(git show:*),
Bash(git diff:*), Bash(git blame:*)` — read-only only, matching the mission
tool grant exactly.

## Schema surface (`schemas/v1.3.0/`)

Fifteen additive schemas, all registered in `lib/protocol/contracts.mjs`
alongside their v1.2.0 counterparts (where one exists):

| Schema | Purpose |
|---|---|
| `operating-mission-packet.schema.json` | The dispatched packet: charter, prior-cycle summary, planning status, role brief, declared roots, tool grant, evidence index, budgets. `additionalProperties: false` at every level — structurally cannot carry a body field. |
| `operating-evidence-index-item.schema.json` | One evidence pointer: path/revision, content hash, source, classification, freshness, sensitivity, signals. No raw-content field. |
| `operating-tool-grant.schema.json` | Closed enum of seven read-only capabilities + confined roots. Cannot express write/exec/network/env. |
| `operating-adapter-handoff.schema.json` (v1.3) | Same envelope as v1.2; `dispatch` now requires `missionPacketPointer`/`declaredRoots`/`toolGrant`/`isolation` (enum: `enforced-read-only-bounded` \| `fail-closed-structured-provider`) instead of `rolePackPointer`. |
| `operating-citation.schema.json` | `oneOf` repository-path(+lineRange) / git-revision / planr-artifact, each requiring `pinnedRevision`. |
| `operating-citation-resolution.schema.json` | `resolved` (requires `evidenceId`+`snapshotDigest`) or `rejected` (requires `reason`+`gapId`). Deliberately carries no `sensitivity`/`classification` field — see verification.md Reviewer Flag (a). |
| `operating-advisor-response.schema.json` (v1.3) | Same as v1.2 but each proposal requires `citations[]`, `minItems: 1`. |
| `operating-finding.schema.json` / `operating-data-gap.schema.json` (v1.3) | Add `citations`; data-gap adds `"unresolvable-citation"` to its category enum. |
| `operating-role-registry.schema.json` (v1.3) | Adds required per-role `dispatchMode: "pack" \| "mission"`. |
| `operating-route-plan.schema.json` (v1.3) | Adds `"create-quick-task"` to `actions[].kind`. |
| `operating-records-log-entry.schema.json` | One line of `.state/records.jsonl`; same field set as `operating-record`. Four branches (`finding`/`data-gap`/`route`/`migration`) accept either a v1.2.0 or v1.3.0 `$ref` for `content` — see verification.md for why. |
| `operating-migration-record.schema.json` (v1.3) | Adds `sourceLayout`/`targetLayout` enum and `recordCount`/`eventCount` before/after pairs. |
| `operating-cadence-status.schema.json` | `cadence` enum, nullable `lastRunAt`/`nextDueAt`. |
| `adapter-registry.schema.json` (v1.3) | Adds `"enforced-read-only"` / `"native-read-only"` to the capability enums, additively. |

## `.planr/operate/` readable layout (FR5)

```text
.planr/operate/
├── brief.md                      # latest cycle brief
├── charter.md
├── cycles/CYCLE-011/
│   ├── brief.md
│   ├── board/{ceo,cto,product,growth,operations,chair}.md   # one per lens, incl. not_evaluated
│   ├── findings.md
│   ├── decisions.md
│   ├── gaps.md
│   ├── routes.md
│   └── evidence-index.json
└── .state/                       # internals, dot-prefixed
    ├── events.jsonl
    ├── records.jsonl              # was: directory-per-digest-prefix
    └── checkpoint.json
```

`records.jsonl` replaces the SPEC-002 directory-per-digest-prefix layout;
migration is automatic, reversible, and lossless (proven by
`lib/operate/records-migration.mjs` and
`conformance/verify-operating-records-migration.mjs`). Route records are
never one file per route in the readable tree.

## `dispatchMode` coexistence (FR10)

The v1.3 `operating-role-registry` schema requires a per-role `dispatchMode:
"pack" | "mission"` so v1.2 role-pack execution and v1.3 mission-packet
execution can coexist during migration, one role at a time, and reduce
identically regardless of which mode produced the result.

**Drift note:** `registry/operating-roles.json` on disk does **not** carry a
`dispatchMode` field on any of its six roles today, even though
US-004/T-004's Definition of Done and Acceptance Criteria describe adding it.
The generator (`lensRolesInOrder()` in
`scripts/generate-operating-assets.mjs`) instead derives `dispatchMode ??
'mission'` in memory at generation time and proves that derived,
dispatch-mode-carrying view validates against
`operating-role-registry@1.3.0` before using it. QA reviewed this as
Deviation #4 in the run manifest / qa-report.md and disposed it "JUSTIFIED,
intent satisfied" because every role currently defaults to `mission` and the
coexistence guarantee holds functionally. It is still a real gap between
what the story text says ships and what is on disk: **there is currently no
way to persist a role at `dispatchMode: "pack"`** without editing the
generator's default, because the field the schema requires is never written
to the registry file itself. A future maintainer rolling one lens back to
pack mode during migration will need to either persist the field for real or
extend the generator's derivation logic — the registry file alone will not
show the intended per-role state.

The parallel `adapterEnforcesBoundedReadOnly()` mechanism in
`lib/operate/adapter-handoff.mjs` has the same shape of gap: `registry/adapters.json`
was never given the new `toolIsolation: "enforced-read-only"` /
`operatingAdvisorDispatch: "native-read-only"` v1.3 fields that
US-002/T-002's acceptance criteria describe; the v1.3 dispatch boundedness is
instead derived from the pre-existing v1.2 `toolIsolation === 'enforced'`
value. QA disposed this as Deviation #3, "JUSTIFIED, intent satisfied." Both
deviations are documented in `.planr/specs/SPEC-004-operating-board-agentic-execution/qa-report.md`.

## Cadence (FR8)

`manual` runs only on request. `weekly`/`monthly` compute a real next-due
date via `computeNextDueDate()` and surface it in `status`, with no
filesystem read, network call, or scheduling side effect. Any optional
scheduled execution the runtime enables MUST NOT accept findings, apply
routes, invoke PLAN, or invoke SHIP — R1 stays mandatory for cadence-
triggered runs exactly as for manual ones.

## Skill-first experience and generated guidance (FR9)

The three generated runtime templates
(`templates/runtime/planr-operate-skill.md.tpl` for Codex,
`templates/runtime/planr-operate-cursor.mdc.tpl` for Cursor,
`templates/runtime/planr-operate-command.md.tpl` for the Claude Code
`/planr-pipeline:operate` command) each state that the skill orchestrates
`prepare → record → finalize` invisibly and that a user is never required to
type an adapter lifecycle subcommand. The `planr operate` CLI remains the
complete, scriptable, authoritative surface for state, locks, validation,
provenance, routing, and recovery.

## Decision briefs (FR7)

`createOperatingDecisionBriefArtifact()` reuses the SPEC-001
artifact-envelope pipeline so a cycle brief or an owner decision opens as one
self-contained, offline HTML artifact — no remote script, style, font, or
image reference — through the same review surface other artifact envelopes
use. Rendering is local and share-on-request; nothing publishes
automatically.

## Route targets (FR6)

| Shape of work | Route target |
|---|---|
| Small, bounded implementation | Quick task (`create-quick-task`, target path under `.planr/quick/`) |
| Substantial product or technical work | Spec + mandatory PLAN review |
| Human or business choice | Decision record |
| Research, content, or report | Agent artifact |

Nothing may invoke SHIP; R1 remains mandatory. `create-quick-task` is the one
genuinely new action kind this feature adds to `operating-route-plan`
(v1.2's enum had no quick-task variant).
