## Header Requirements

```yaml
# Task-{M} — [Descriptive Title]
# US: us-{N} — [US Title]
# Feature: feat-{name}
# Agent: [Frontend Agent | Backend Agent] (Opus 4.7)
# Type: [UI | Tech]
# Status: [pending | in-progress | complete | failed]
```

Rules:
- Title must be specific (not "Create components" but "Create UserProfileCard component with avatar and edit button")
- Agent must match Type (UI → Frontend Agent, Tech → Backend Agent)
- Status starts as `pending`, updated by agents during execution

## File List Requirements

### Create List
```
- Every file to be created must have an ABSOLUTE path from project root
- File must not already exist (or agent must be explicitly told to overwrite)
- Path must match naming convention in stack.md
- Include a one-line description of purpose
```

✅ Good:
```markdown
- `src/features/auth/components/LoginForm.tsx` — Login form with email/password fields
```

❌ Bad:
```markdown
- Create a login form component
```

### Modify List
```
- Every file to be modified must exist at the given path
- Describe WHAT change is needed, not just which file
- Be specific enough that the agent doesn't need to guess
```

✅ Good:
```markdown
- `src/app/layout.tsx` — Add AuthProvider wrapper around {children}
```

❌ Bad:
```markdown
- Update the layout file
```

### Preserve List
```
- List every file that the agent might accidentally touch but MUST NOT
- Include files in the same directory as Create/Modify targets
- Include shared files that could be impacted by the changes
```

## Technical Spec Requirements

### UI Task (task-1):
- Must name every component with its props interface
- Must specify route paths if creating pages
- Must reference design-spec.md section numbers for token application
- Must describe state shape and where it lives
- Must name API endpoints to wire up (by name, not implementation)

### Tech Task (task-2):
- Must specify every endpoint: METHOD + path + request/response shape
- Must name every service with its method signatures
- Must define all DTO structures (not vague — actual fields)
- Must reference specific DB tables and columns from schema.json
- Must describe business logic rules explicitly

## Validation Checklist (used by /review-tasks)

```
✅ Header complete with all 6 metadata fields
✅ Objective is one clear paragraph (not bullets)
✅ At least 1 file in "Create" OR 1 file in "Modify" (can't be empty)
✅ All "Create" paths don't already exist (or are flagged as overwrite)
✅ All "Modify" paths reference real existing files
✅ "Preserve" list is non-empty (even if just "none — no protected files")
✅ Technical spec covers all items in the Create + Modify lists
✅ Test requirements are specific (not "write tests")
✅ Definition of Done has at least 4 checkboxes
```
