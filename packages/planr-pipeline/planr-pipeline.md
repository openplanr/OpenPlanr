# Planr Pipeline — Cross-runtime reference

> Generated by OpenPlanr on 2026-05-03
> Pairs with `CLAUDE.md` (sibling). OpenPlanr Protocol v1.0.0 — runtime-agnostic contract.

This project uses the portable **planr-pipeline** package. Nine canonical roles
orchestrate PO → Design → Review → DEV → QA through native Claude Code, Codex,
or Cursor adapters.

## Install (one-time)

```bash
curl -fsSL https://openplanr.dev/install.sh | sh
cd my-project
planr setup
planr doctor
```

The installer changes no project files. `planr setup` interactively detects
coding agents, lets the user select integrations, and previews owned changes.
Legacy Claude marketplace commands remain supported during the compatibility
window, but guided setup is the primary installation path.

## Workflow commands

| Command | Phase | What it does |
|---|---|---|
| `planr pipeline plan {feature}` | PO Phase | Auto-scaffolds spec shell if missing → design/specification roles. STOPS for human review (rule R1). |
| `planr pipeline ship {feature}` | DEV Phase | Implementation roles → QA gate → delivery outputs → `.pipeline-shipped` marker. |

Claude Code users may continue using `/planr-pipeline:plan` and
`/planr-pipeline:ship`; Codex uses installed skills and Cursor uses Composer
handoff. All adapters share the same deterministic engine.

## Hard rule R1 — never auto-chain

**The pipeline refuses to chain PO → DEV automatically.** A human review step
between `/planr-pipeline:plan` and `/planr-pipeline:ship` is mandatory.
This is the most important rule and the differentiator of the workflow.

## Spec-driven mode (recommended)

If `.planr/config.json` declares `idPrefix.spec`, the pipeline reads from
`.planr/specs/SPEC-NNN-{slug}/` directly — no conversion. Same artifacts the
planr CLI authors. Two products, one schema.
