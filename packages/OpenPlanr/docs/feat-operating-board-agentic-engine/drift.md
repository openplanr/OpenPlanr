## Recorded, justified deviations (not drift — the spec's intent holds)

These are deliberate implementation choices that satisfy the FR's intent
through a different mechanism than the task text's literal wording, each
already disposed as justified in `qa-report.md`'s Deviation Disposition
Register:

- **FR1 / T-002:** the task text said to bump `OPERATE_PROTOCOL_VERSION` from
  `'1.2.0'` to `'1.3.0'`. The code instead adds an additive
  `OPERATE_MISSION_PROTOCOL_VERSION = '1.3.0'` constant
  (`src/services/operate/types.ts:1,16`), leaving the original constant
  frozen at `'1.2.0'`. This is the correct call: bumping the shared constant
  would have broken the "v1.2 project runs unmodified" guarantee FR3 and FR8
  depend on.
- **FR4 / T-003:** `dispatchModeOverrides` lives in machine-local
  `preferences.json` (`src/services/operate/config.ts:277-286`) rather than
  the schema-frozen `operating-config` artifact. The v1.2 on-disk config
  schema is a published, frozen contract (`additionalProperties: false`);
  adding a field to it would have broken validation for every existing v1.2
  project.
- **FR10 / T-009:** all four version pins read `0.33.1`/`v0.33.1`, not the
  `0.33.0`/`v0.33.0` the spec and task text literally name. A forward-fix
  release of the pipeline package occurred between planning and dispatch;
  `0.33.1` is the currently-installed, currently-correct target and every pin
  location is consistent with it (verified in `package.json:96` and
  `.github/workflows/ci.yml:28`).

None of these weaken any FR's guarantee; all three are documented in
`implementation.md` under their respective tasks.

this feature's mandate to touch them. QA's Follow-Up Register (item 1)
