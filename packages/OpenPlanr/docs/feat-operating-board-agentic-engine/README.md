# Operating Board Agentic Engine (Protocol v1.3)

Spec: `SPEC-001-operating-board-agentic-engine` · Engineering companion:
[`docs/implementation/OPERATE-SPEC-004.md`](../implementation/OPERATE-SPEC-004.md) ·

## What this feature is

This is the runtime half of the Operating Board's move to Protocol v1.3. The
umbrella spec (owned by the pipeline package this repo consumes) defines the
v1.3 contracts — mission packets, citation resolution rules, the storage
migration transform, cadence calculation — as pure modules with fixtures. This
repository (`OpenPlanr`) implements the live, on-disk, real-repository half of
every one of those contracts: the evidence index that actually walks a git
workspace, the dispatch code that actually runs advisory lenses with a bounded
tool grant, the citation resolver that actually reads files at a pinned
revision, the migration that actually rewrites a project's `.planr/operate/`
tree, and so on.

Ten user stories (US-001…US-010) map 1:1 to ten functional requirements
(FR1…FR11 — FR2/FR4's dispatch mechanics were folded into a single story,
US-003) and ten tasks (T-001…T-010). All ten tasks are `type: "Tech"`; there is
no UI surface in this feature (backend-only engine work), so there are no
design-fidelity concerns and no PNG mockups in this bundle.

## What v1.3 delivers, capability by capability

**Storage-layout migration (US-001).** Any mutating `operate` command that
opens a project still on the old (SPEC-002) on-disk layout migrates it
automatically, journal-safely, to the new layout before the command proceeds:
internals collapse under a dot-prefixed `.state/` directory
(`events.jsonl`, a single append-only `records.jsonl`, `checkpoint.json`),
and a readable Markdown/JSON tree renders at the top level (`charter.md`,
`brief.md`, `cycles/CYCLE-NNN/board/*.md`, `findings.md`, `decisions.md`,
`gaps.md`, `routes.md`, `evidence-index.json`). Migration is reversible
(`operate migrate rollback` restores the prior layout byte-exact) and
crash-safe — including a genuine data-loss defect this feature's own test
suite found and fixed; see `implementation.md` for the full arc.

**Evidence-index mission packets (US-002).** Instead of pre-loading
role-filtered file bodies into an advisor's context (SPEC-002's model — one
real CTO pack duplicated 274,778 of 405,820 bytes as source text), the engine
now builds a compact **index**: path, pinned revision, content hash,
classification, freshness, sensitivity, and detected signals — never file
bodies. The cycle's git revision is pinned once at cycle start and recorded
identically in the manifest, the index, and every mission packet; all citation
resolution binds to that pin. Mission budgets (single-digit KiB per role) come
from a v1.3 derived registry and fail closed with
`E_OPERATE_MISSION_PACKET_BUDGET` before any dispatch call, without touching
the v1.2 on-disk budgets pack mode still uses.

**Bounded native advisor dispatch (US-003).** Advisory lenses can now run as
native, read-only agents against the real repository — confined to declared,
sensitivity-ceiling-narrowed roots, with exactly a read-only tool grant (glob,
file read, content search, read-only git history) and nothing else: no write,
no exec, no network, no environment access. Lenses fan out in parallel when
the calling adapter reports it supports concurrent dispatch, sequentially
otherwise, and the two modes reduce to byte-identical results. A per-project
`dispatchModeOverrides` map in machine-local preferences lets an operator pin
an individual role back to the old pack path without waiting for a registry
release. Any adapter that cannot itself enforce the read-only/path-confined
boundary at runtime never receives a native lens — it falls back to the
structured-provider path instead, and that reconciliation is recorded
explicitly in the dispatch result.

**Citation resolution as the audit mechanism (US-004).** Findings no longer
just cite "evidence IDs present in the input" — they cite a real repository
path and line range, a git revision, or a planr artifact ID, and the engine,
not the advisor, is the trust boundary. Every citation is resolved against the
cycle's pinned revision after the advisor returns; resolved content is
snapshotted through the existing redaction and secret-scan path into
machine-local evidence; an unresolvable citation is rejected fail-closed into
a gap and never reaches consolidation. Fabricated paths, out-of-range lines,
moved revisions, and citations into uncommitted (dirty-tree) content each
reject with a distinct, named reason — dirty-tree is deliberately not
conflated with fabrication, so in-flight legitimate work is never silently
discarded.

**Create-quick-task routing (US-005).** An accepted finding classified as
small, bounded implementation work now routes to a real
`.planr/quick/QUICK-NNN-{slug}.md` file — not just to a spec, decision, or
agent artifact — through the same accept≠apply, digest-preview, write-ahead
journal, and byte-exact-rollback machinery every other route already uses. No
route, including this new one, ever invokes SHIP.

**Offline decision briefs (US-006).** `operate brief` and
`operate decisions show` can render a self-contained, offline HTML artifact —
question, cited evidence, options, and what a decision blocks — reusing the
existing opaque-origin sandbox contract (no network, no filesystem, no tools).
Rendering is local and share-on-request only; nothing publishes automatically,
and the same sensitivity ceilings that gate collection and dispatch also gate
what appears in rendered content.

**Cadence state and the never-acts guarantee (US-007).** `lastRunAt` is now
persisted per project, and `operate status` surfaces `nextDueAt` for weekly
and monthly cadence (`null` for manual) via a pure, injected-clock calculator.
The load-bearing guarantee: even a cadence-triggered run stops at
`reviewable` — it can never accept a finding, apply a route, or invoke
PLAN/SHIP, and this has an explicit, named test rather than an inference from
absence of a call.

**Skill-first cycle (US-008).** A scripted run proves a full cycle — inspect
→ init → run → native lens dispatch → record → finalize → chair → review —
completes with zero user-typed adapter lifecycle commands, entirely through
the JSON action surface the skill/plugin runtime drives. The CLI remains the
authoritative, scriptable state machine underneath.

**Doctor v1.3 hardening (US-009).** `planr doctor` gained three additive
diagnostics — storage-layout consistency, records-log integrity, and
dispatch-mode validity — on top of the existing diagnostic surface, with no
change to any pre-existing diagnostic's code, status, or message shape. The
packed-install end-to-end test and all four version-pin locations
(`package.json` plus three CI workflow refs) were moved together to
`planr-pipeline@0.33.1`.

**Coordinated release preparation (US-010).** This repository's only release
artifact is a Changesets entry recording the `openplanr` `1.16.2` → `1.17.0`
minor bump pinned to `planr-pipeline@0.33.1`. Every sibling-repository step
(skills package release, marketplace update) is recorded as an explicit,
unchecked "external action" checklist item — this repository never writes
into a sibling repository.
