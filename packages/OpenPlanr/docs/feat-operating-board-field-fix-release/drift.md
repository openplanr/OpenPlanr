  `options?: { protocolVersion?: string }` parameter beyond the literally-named

  responses against the correct schema version. Additive, non-breaking.

  `resolveOperatingPackBudget()`), not a field added to a readiness type; the existing
  `E_OPERATE_EVIDENCE_BUDGET` code is reused rather than minting a new

  field. Two dead-session state-machine assertions were kept (with supersede tests added
  beside them) rather than deleted, and the finalized-branch error code was corrected
  in-place from what the task text literally named. None of this weakens the FR4
  guarantee — confirmed by the passing supersede test asserting neither the old nor a
  new invalid-state code is thrown.
- **FR5 / T-006:** `isAIConfigured` was kept synchronous (15 out-of-scope callers left
  untouched) rather than converted to async; the new `resolveAIProviderReadiness` is
  additive. The run-preview integration proof was delegated to T-004's file

- **FR9 / T-007:** `types.ts` was not touched — `preselected` validates against the
