# Operating Board Field-Fix Release

Spec: `SPEC-002-operating-board-field-fix-release` · QA verdict: **PASS** (single round,
no retries — see [`implementation.md`](./implementation.md)) · Target release:
`openplanr@1.18.0` pinning `planr-pipeline@0.34.0`.

## Where this release comes from

Protocol v1.3's runtime half shipped in the previous release
(`SPEC-001-operating-board-agentic-engine`, documented in
[`../feat-operating-board-agentic-engine/`](../feat-operating-board-agentic-engine/)).
The first real-world run of that stack (CLI 1.17.0 · pipeline 0.33.1 · skills 1.19.0)
against a production repository surfaced, and a two-round code-level field audit
confirmed, that the flagship capability was unreachable and the first-run experience was
broken in specific, reproduced ways:

1. **Mission dispatch was production-dead.** No traveled code path consulted
   `resolveOperatingDispatchMode` for execution; `buildOperatingMissionPackets` had zero
   production callers; the adapter handoff defaulted `protocolVersion` to `1.2.0`,
   locking every record action to the v1.2 pack path; the six generated lens agents were
   registered but dispatched by nothing. A real 2,736,185-byte pack shipped against a
   384 KB registry contract because pack input budgets were still unenforced.
2. **The first `operate run` crashed with a masked error** — an unconfigured-provider
   error surfaced as a generic `E_OPERATE_INTERNAL` — caused by a cascade starting with
   missing runtime detection in the guided path (adapter stamped `unknown`/`none` →
   `auto` persisted → native dispatch silently disabled → provider path → unguarded key
   error).
3. **Machine-local state collided across board generations** (adapter sessions and the
   incremental evidence cache carried no board identity), producing a misleading
   `E_OPERATE_STATE_INVALID` and forcing whole-cycle cancellation.
4. **Human surfaces leaked machine JSON** (`operate review` had no human renderer) and
   healthy continuations rendered as failures (exit 4 on every successful guided-stage
   advance).
5. **The onboarding questionnaire carried dead weight and traps** — a write-only
   timezone question, unconfigurable `github`/`linear` source choices that always failed
   validation, suggested defaults that never pre-checked, and dropped charter deferral
   defaults.

This release closes all twelve functional requirements (FR1–FR12) the audit produced.
Nine user stories (US-001…US-009) map 1:1 to those FRs (FR4/FR11 fold into US-005; FR3,
FR7, and FR8 fold into US-004) and nine tasks (T-001…T-009). All nine tasks are
`type: "Tech"`; this is backend/CLI engine work with no UI surface, so there is no
design-fidelity concern and no PNG mockups in this bundle (confirmed by QA: no
`design/design-spec.md` exists under the spec directory, and no task carries
`Type=UI`).

## What this release delivers, capability by capability

**Mission dispatch wired end-to-end — the packet-not-pack proof (US-001, US-003).**
`operateAdapterLifecycle` prepare now actually resolves each role's dispatch mode via
`resolveOperatingDispatchMode` and `operatingRuntimeEnforcesBoundedReadOnly`, and roles
that resolve to `mission` get a real `buildOperatingMissionPackets` output stored in the
session and exposed at `/data/missionPackets/<role>` — not a rolePack. `protocolVersion:
'1.3.0'` now reaches `protocol.createOperatingAdapterHandoff` from both call sites in
`maintenance.ts` whenever any bound role resolved mission, so the record action carries
`dispatch.agent` and `dispatch.missionPacketPointer` instead of `rolePackPointer`. A new
end-to-end test, `tests/unit/operate-adapter-mission-dispatch.test.ts`, proves a mission
packet — not a pack — reaches the record action on a native-capable runtime, that
`--dispatch-mode-override` is execution-effective in both directions, and that
`provenance.dispatchMode` never claims `mission` when a pack was actually sent. On the
pipeline side, `planr-pipeline@0.34.0` now names the generated lens agent
(`dispatch.agent: "operating-<roleId>"`) and publishes the operating-roles registry at
protocolVersion 1.3.0 with an explicit per-role `dispatchMode`.

**Pack budgets fail closed at field-incident scale (US-002).** `createOperatingAdvisorPack`
now measures the canonicalized pack against the role's `budgets.maxInputBytes` and fails
closed with a typed error (reusing `E_OPERATE_EVIDENCE_BUDGET`) at both the
`dispatchOperatingAdvisors` call site and the `operateAdapterLifecycle` prepare call
site. A dedicated scale test replays the field incident's exact byte count
(`FIELD_INCIDENT_BYTES = 2_736_185`) against a real ~384 KB role budget and proves the
pack is rejected before any provider or adapter call. The false docstring claiming "pack
mode still enforces" the budget is corrected in place.

**A human review renderer (US-004).** `planr operate review` without `--json` now
renders Markdown — reusing the same brief/lens-report assembly `reports.ts`'s
`readOperatingReport` already builds for the `report` command — instead of falling
through to `JSON.stringify(result.data)`. `--json` still returns the exact raw state
object, unchanged.

**`ok:true` continuations and executable `confirmArgv` (US-004).** Guided-stage advances
(`E_OPERATE_INPUT_REQUIRED`) and first-use provider consent
(`E_OPERATE_AUTHORITY_REQUIRED`) now return an `ok:true`, `flow: "handoff"` shape instead
of a bare `ok:false`/exit-4 failure — mirroring `run`'s existing handoff treatment.
Structured actions gained a `confirmArgv` field so a runner never has to
re-synthesize a stripped confirmation token, and no `confirmationDigest` attaches to a
command (like `run`) that accepts no `--confirm` flag. Mutation confirmations
deliberately keep the old `ok:false`/exit-4 shape — the authority model is unweakened.

**Board-identity binding and doctor staleness diagnostics (US-005).** Adapter sessions
and the incremental evidence cache now carry the board's event-chain genesis hash, so a
re-inited board never collides with a prior generation's machine-local state. The
evidence cache honors its own already-written `workspaceDigest`: a mismatch is treated
as no-baseline and triggers a deep recollect instead of trusting stale evidence. A
committed `operate init` apply purges `<localRoot>/advisors/` and
`<localRoot>/evidence/incremental/`. A finalized or expired adapter session is now
superseded instead of forcing a whole-cycle-cancelling `E_OPERATE_STATE_INVALID`. `planr
operate doctor` gained two new diagnostics (`operate-adapter-sessions`,
`operate-incremental-baseline`) with scoped repair commands, and post-upgrade
lock-drift now presents as expected-after-upgrade rather than a FAIL implying Operating
Board breakage — but only when the drift is CLI-component-only; a stale skill bundle or
digest/adapter drift still fails.

**Typed provider errors and real runtime detection (US-006).** A provider bootstrap
failure (e.g. a missing API key) now surfaces as a typed `E_OPERATE_ADVISOR_FAILED`
carrying the actionable remedy ("planr config set-key … / --offline"), never a
zero-information `E_OPERATE_INTERNAL`. When `E_OPERATE_INTERNAL` is returned, it now
carries a redacted error class/name. A preflight key-resolution check lets `run
--preview` name a missing key before a cycle starts. The JSON init path now probes real
runtime identity (environment markers specific to each supported host environment)
instead of stamping `{"runtime":"unknown","interaction":"none"}`, and a persisted
`"auto"` preference resolves to the detected host — closing the exact crash chain the
field run hit.

**Questionnaire diet, preselection, and `--answers-file` (US-007).** The write-only
`timezone` question is removed entirely. `cadence` and `component-roots` no longer block
the first-run batch — the question engine now returns only required-and-missing plus
explicitly-flagged questions, not every unanswered visible one. `github`/`linear` are
removed or gated from the sources choice list until they are actually configurable
in-flow. `planning-engine` suggests `pipeline-po` when planr-pipeline is installed;
`decision-owner`'s git-user suggestion now reaches the JSON/native init path, not only
the terminal path. Charter deferral defaults ("Not yet specified") are restored on
business-model and ideal-customer, `known-unknowns` becomes optional, `product-stage`
becomes a real select, and `guardrails` is seeded with the engine's standing boundaries
as suggestions. Per-choice `preselected` now carries schema-to-UI and renders
pre-checked, never fabricating a select from repeated text. `--answers-file <path>` is a
new bounded stdin-parity alias.

**Adapter lease ergonomics (US-008).** The previously hardcoded 15-minute adapter
session lease is now surfaced in prepare and handoff output (expiry + remaining),
refreshed on each successful `record`, and configurable via machine-local preferences
(bounds-validated, fails closed on an out-of-range value rather than silently clamping).
The existing recovered-roles-by-input-digest recovery path is unchanged, only exposed
more visibly.

**The pipeline 0.34.0 contract half (US-001).** `planr-pipeline@0.34.0` — published,
tagged, and merged as a precondition every engine-side task pins — ships the
`dispatch.agent` field, the additive `preselected` schema field, the 1.3.0 role and
adapter registries, and the mission-branch documentation in `commands/operate.md` and the
generated skill template.

**Coordinated release prep (US-009).** This repository's release artifact is a
Changesets entry recording the `openplanr` `1.17.0` → `1.18.0` minor bump pinned to
`planr-pipeline@0.34.0`. Every sibling-repository step (`@openplanr/skills@1.20.0`, the
marketplace `SPEC-005` ledger entry) is recorded as an explicit, unchecked "external
action" checklist item — this repository never writes into a sibling repository.
