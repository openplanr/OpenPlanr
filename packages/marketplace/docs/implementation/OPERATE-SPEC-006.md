# OPERATE-SPEC-006 marketplace work item

Umbrella specification: `SPEC-006`  
Release participant: `openplanr-marketplace@1.6.0`

Marketplace owns the coordinated saga ledger and the revised
`agenticOperatingBoard` compatibility capability for the truthful-outputs and
epic-loop release of the Operating Board execution train. The verified
SPEC-002, SPEC-003, SPEC-004, and SPEC-005 records remain immutable.

The release records pipeline `0.35.0` (mission-packet evidence caps enforced
as a loudly-reported truncation that follows caller priority, the additive
`create-epic` action kind on the v1.3 operating-route-plan schema, per-role
mission budgets re-sized against real index-item byte costs, and the
regenerated operate assets), OpenPlanr `1.19.0` (truthful cycle outputs
persisted as files from a single rich assembly, so the cycle report is
byte-identical to the review rendering and every role board carries
impact/confidence/ease recommendations; evidence loss never silent, with
capped walks naming the last path reached and the directories left unscanned,
dropped mission-index entries counted as warnings, and a starved role gated
not-ready while ready roles still dispatch; a prioritized, fair collection
pass over per-directory round-robin plus git-recency ordering; re-init that
preserves machine-local preferences and previews any that will change; and the
epic loop closed by grouped accepted findings emitting a ready-to-run epic
suggestion and a governed `create-epic` route that writes a real
`.planr/epics` artifact through the write-ahead journal with byte-exact
rollback), and skills `1.21.0` (the operate skill re-mirrored and validated
byte-for-byte against pipeline 0.35.0).

The pipeline adapter registry continues to declare protocol `1.3.0`, so this
release leaves the resolved manifest's `protocol.current` unchanged at `1.3.0`
and revises the existing capability rather than opening a new protocol line.
Advisor dispatch capability per adapter is unchanged from the SPEC-004
classification: native read-only dispatch on hosts with parallel subagents;
structured-provider fallback elsewhere. The epic route writes planning
artifacts only — it never invokes PLAN or SHIP, and cadence-triggered runs
remain review-only.

Before publication each participant may compensate locally; after an npm
package is public, recovery is forward-fix only.
