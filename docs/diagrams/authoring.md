# Authoring and verifying semantic diagrams

OpenPlanr diagrams separate intent from rendering. The canonical Protocol 1.6
document describes meaning; `@openplanr/artifact/diagram` deterministically
validates, lays out, and projects that document into editable and presentation
formats. Skill prose helps an agent choose and structure a diagram, but it never
owns renderer algorithms or generated bytes.

Use Node.js 26 for normal repository work. Release proof also runs the public
tarballs under Node.js 20 and 22.

## First diagram

Discover the registry-owned grammars, then render a canonical document:

```bash
planr diagram gallery
planr diagram render ./architecture.planr-diagram.json --json
```

In a Git repository the default output is `diagrams/{slug}/`. Outside a
repository, OpenPlanr uses a disposable temporary directory and reports that
path. Pass `--output <directory>` when the result must be retained explicitly.

A complete set contains the canonical source, a Mermaid or Excalidraw projection
when that grammar supports it, SVG, PNG, accessible HTML, quality and fidelity
reports, plus one manifest binding the set. Unsupported conversions are reported
as omissions; they are never presented as lossless.

Inspect or verify an existing set with its manifest:

```bash
planr diagram inspect ./diagrams/architecture/architecture.manifest.json --json
planr diagram check ./diagrams/architecture/architecture.manifest.json --json
```

After editing a supported source projection, rerender from that explicit source:

```bash
planr diagram rerender ./diagrams/architecture/architecture.manifest.json --accept excalidraw --json
```

`check` reports source or generated drift without rewriting files. `rerender`
accepts only the selected source and regenerates the rest of the set.

## Mermaid and natural-language input

The CLI imports the supported Mermaid flowchart subset directly:

```bash
planr diagram render ./flow.mmd --json
```

For natural-language intent, invoke `planr-diagram` in the active coding host.
The skill reads the relevant source context, chooses a grammar and semantic
pattern, asks at most three native structured questions when a consequential
choice remains unclear, and writes canonical IR before invoking the deterministic
CLI. Its progressive references are:

- `skills/planr-diagram/references/diagram-intent-to-ir.md` for grammar and semantic
  pattern selection;
- `skills/planr-diagram/references/diagram-fidelity.md` for editability, accessibility,
  split, and omission decisions.

## Review and downstream consumers

Open the generated HTML on the existing canvas review surface:

```bash
planr artifact ./diagrams/architecture/architecture.html --presentation canvas
```

The artifact integration binds review pins to the exact manifest and envelope
bytes. Specification, documentation, and PDF consumers use Protocol 1.6
`diagram-consumer-reference` documents, so they point to the same verified set
instead of copying or re-rendering it.

## Add or change a grammar

Grammar ownership is intentionally narrow:

1. Edit the canonical definition in
   `packages/protocol/scripts/diagram-definitions.mjs`.
2. Add or update the corresponding semantic model and routing behavior under
   `packages/artifact/lib/artifact/diagram/`.
3. Run `npm run generate`. The generator creates the grammar fixture, progressive
   reference, gallery entry, Protocol registry, and public pipeline projection.
4. Add a focused assertion under `packages/artifact/tests/` when behavior changes.
5. Run the checks below. Do not edit generated fixtures or adapters directly.

```bash
npm run check:generated
node --test packages/artifact/tests/diagram-*.test.mjs
npm exec --workspace=openplanr -- vitest run tests/integration/diagram-command.test.ts
```

The drift report names the owning canonical definition and generated target. Fix
the owner, regenerate once, and rerun check mode; contributors never copy or
approve content digests by hand.

## Skill modules, matching, and release proof

Use the companion guides for the rest of the skill fabric:

- [composed skill modules and generation](../skills/authoring.md);
- [host matching, structured questions, and lifecycle](../skills/host-runtime.md);
- [versioning, impact analysis, and learning proposals](../skills/versioning-and-impact.md).

Before committing a catalog or diagram change, run:

```bash
npm run skill:lint -- skills/planr-diagram
npm run skill:preview -- skills/planr-diagram
npm run skill:evaluate -- skills/planr-diagram
npm run check:generated
npm run test:focused
npm run verify:packed:strict
```

The packed proof installs the three public `openplanr`, `planr-pipeline`, and
`@openplanr/protocol` tarballs,
runs `planr diagram gallery`, renders and checks a fixture, verifies aliases and
exports, and proves the packages do not depend on private workspaces or sibling
repositories.
