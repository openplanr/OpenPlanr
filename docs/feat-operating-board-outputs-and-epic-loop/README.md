# Operating Board Truthful Outputs, Evidence Integrity, and the Epic Loop

Spec: `SPEC-003-operating-board-outputs-and-epic-loop` · QA verdict: **PASSED** (round 1
PASS with two adjudicated, non-blocking deviations; a round-2 re-audit closed one of
them — see [`implementation.md`](./implementation.md) and [`testing.md`](./testing.md))
· Target release: `openplanr@1.19.0` pinning `planr-pipeline@0.35.0`.

## Where this release comes from

Round 3 of the field audit was different from rounds 1 and 2: it watched a complete,
successful operating cycle — **CYCLE-007**, run on the production monorepo, under the
stack the previous release shipped (CLI 1.18.0 · pipeline 0.34.0) — run end to end
without crashing. The verdict was not "it's broken." It was worse to diagnose: **a good
advisory engine sitting behind a failing persistence layer**. The cycle's lens agents
produced roughly 30 KB of scored, cited analysis; almost none of it reached a file. The
file tree an operator would actually read was a readable index onto an unreadable
database, with a broken pointer at the one place a human was told to look next.

Three findings drove this spec:

1. **The cycle's intelligence never reached files.** Board files were 308-byte stubs
   whose only escape hatch was a broken CLI flag; two renderers existed side by side —
   a cheap, capped one that persisted, and a rich one that only ever rendered
   transiently for `review`/`report`. The brief dropped most findings and gaps, two
   briefs contradicted each other, and files claimed roles were "evaluated" that never
   ran.
2. **Evidence could vanish silently, three filters deep**, and a role could dispatch
   "ready" on an empty evidence base with no gap and no warning — the real cycle
   indexed 1,001 files and delivered zero product code to any advisor.
3. **The loop didn't close.** Findings routed one at a time; nothing grouped related
   findings into a theme, and nothing created an epic, even though this repository
   already owned `planr epic create` and had extended the route-kind enum additively
   once before.

This spec closes all nine of the functional requirements that audit produced (FR1–FR9),
across seven user stories (US-001…US-007) and seven tasks (T-001…T-007, plus a T-006
reachability completion dispatched after the round-1 QA gate — see below). All seven
tasks are `type: "Tech"`; this is backend/CLI engine work with no UI surface, so there
is no design-fidelity concern and no PNG mockups in this bundle (no
`design/design-spec.md` exists under the spec directory, and no task carries
`Type=UI`).

## What this release delivers, capability by capability

**FR1 — files are the source of truth, the centerpiece (US-002).** `cycles/<id>/report.md`
now carries the complete, uncapped `readOperatingReport().markdown` — every lens report,
recommendation, I/C/E score, evidence reference, gap, and conflict — exempt from the
900-word brief cap. `cycles/<id>/board/<role>.md` renders each evaluated role's
persisted advisor-result record through the same rich `markdownLens` renderer the live
`review`/`report` commands use, not the old 28-word-capped, `enabledRoles`-derived
stub; a role with no advisor-result record states plainly that it was not evaluated.
Board `Status:` now derives from whether an advisor-result record actually exists, not
from `config.enabledRoles`, and the report hint reads the real
`planr operate report <cycleId> --lens <role>` syntax instead of a `--cycle` flag that
never existed. `findings.md`/`routes.md` carry full finding and route substance, not
digest-only summaries.

**FR2 — evidence is never lost silently (US-003).** Every filter that removes evidence
now reports what it removed: dot-prefixed/pattern-rejected mission-index items are
counted into `evidence.warnings`; a `maxFiles` truncation mid-walk records the last
path reached and the top-level directories never scanned; sensitivity narrowing now
removes only the individual above-ceiling item, not the whole component root it lives
under. When a role's post-index evidence retains zero repository items, that role is
excluded from dispatch with a governed `operating-data-gap` instead of running "ready"
on nothing — while every other ready role still dispatches.

**FR3 — prioritized, fair collection (US-003).** Pure-alphabetical `git ls-files` →
`.sort()` collection is replaced with per-top-level-directory round-robin selection
weighted by git recency, so a capped monorepo walk samples `apps/`, `packages/`, and
`infra/` instead of exhausting the cap on dotfiles and planning trees first. The
repository and planr providers now draw from split file budgets instead of one shared
counter.

**FR4 — mission budgets sized for real repositories (US-004).** The derived per-role
mission packet budget clamp is raised from an arbitrary 1–9 KiB ceiling to 1–32 KiB
against real index-item costs, so a role like `technology-risk` is no longer starved
below its registry-sized budget. The published pipeline's `maxEvidenceItems`
enforcement — recorded but never applied before this release — is now actually threaded
through mission-packet construction and its truncation surfaced as a cycle warning,
never a silent drop and never an unexplained fail-closed on a healthy repository.

**FR5 — re-init preserves machine-local preferences (US-005).** `operate init` re-runs
no longer silently wipe `dispatchModeOverrides`, `adapterLeaseDurationMs`, and
`lastRunAt` — the exact preferences a real cycle lost this way. `prepareOperatingInitialization`
now merges the existing `preferences.json` forward whenever the operator doesn't
explicitly pass a new value, and the init preview names exactly which preference keys
will change.

**FR6 — backlog promotion and projections retirement (US-002).** The legacy
`.planr/operate/projections/` directory — three files byte-identical to the top-level
readable tree, plus `backlog.md`, which was the only home of parked findings' full
reasons — is retired. `backlog.md` is promoted to the top-level tree; `state.json` is
the sole surviving canonical projection and relocates under `.state/`.

**FR7 — epic loop, interim rendering (US-006).** The cycle report's "Exact next
actions" now groups related accepted findings (shared category, fingerprint lineage, or
Chair merge-proposal source) and emits one ready-to-run
`planr epic create --title "…"` suggestion naming the member findings.

**FR8 — epic loop, full route-kind closure (US-006).** `create-epic` is now a valid,
schema-governed v1.3 route-plan action kind. The engine elects N≥2 related accepted
findings into one `create-epic` route; applying it writes a real
`.planr/epics/EPIC-NNN-<slug>.md` document — reusing the CLI's own epic-creation seam —
through the write-ahead journal, with byte-exact rollback like every other route kind,
and provenance threads forward the same way the existing `create-spec` route threads a
spec id. Accept ≠ apply and R1 hold: a `create-epic` route never invokes PLAN or SHIP.
Round 1 QA found the mechanism correctly built and tested but reachable only by calling
its builder function directly — no CLI command or engine pass ever created one in
production. A scoped completion, dispatched after the round-1 gate, closed that gap
without adding any new CLI surface: `governOperatingFinding` now re-evaluates epic
election on every finding acceptance, so `planr operate findings accept` →
`planr operate routes apply` → `planr operate routes rollback` — all pre-existing,
generic verbs — genuinely elect, preview, apply, and roll back a `create-epic` route.
See [`implementation.md`](./implementation.md) for the full trace.

**FR9 — coordinated release (US-001, US-007).** `planr-pipeline` **0.35.0** ships first —
the `maxEvidenceItems` enforcement half of FR4, the additive `create-epic` schema half
of FR8, and a registry role-budget review — as the external-publish precondition every
dependent engine task pins. This repository releases **openplanr 1.19.0**; skills
**1.21.0** mirrors; the marketplace **OPERATE-SPEC-006** two-step ledger is checklisted
as an explicit external action, not performed by this repository.
