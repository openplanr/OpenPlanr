# Skill source versioning and impact

Each skill package carries one `skillVersion` in `skills/registry.json` and its
`openplanr.skill.json`. A version describes the package contract; generated bytes
do not inherit a skill version by accident.

| Dimension | Version field | Editorial | Compatible addition | Behavior change | Breaking change |
| --- | --- | --- | --- | --- | --- |
| Skill | `skillVersion` | patch | minor | minor | major |
| Generated asset contract | `assetVersion` | patch | patch | minor | major |

Run impact analysis before changing a resource that several packages share, such
as a reference copied from `skills/shared/`. The module ID is the resource file
name without its extension:

```bash
npm run skill:impact -- --module operate-advisor-contract
```

The report names every dependent skill and generated projection. Make the source
edit and its appropriate version change together, regenerate once, then run the
catalog evaluation.

The `--host-profile` and `--host-source` options, and the composed-source layers
they describe (`moduleVersion`, `hostProfileVersion`), belong to the retired
composed authoring format. The compiler for that format stays in
`packages/skill-runtime/src/authoring` only to keep its contract tests and the
`examples/skills/minimal-composed` fixture readable; no shipped skill uses it, and
standard packages report no host profiles.

Local learning is proposal-only. `createLearningProposal` returns a redacted plain
document and has no filesystem write or source-edit capability. A proposal that is
accepted and passes evaluation is eligible for a maintainer to make an explicit
canonical edit; promotion itself never mutates source.
