## Crash-injection methodology (T-001 retry)

`tests/integration/operate-storage-migration.test.ts` reproduces the fixed
migration defect end to end rather than mocking any part of the code under
test:

1. **Fixture independence.** `seedSpec002Project` builds a genuine old-layout
   project using only a real git repo, a real `operate init`, and one real
   `runOperatingCycle` — then down-converts the committed `.state/` view into
   the old directory-per-digest shape using `event-store` field mappings and
   `canonicalize` directly, never calling `migration.ts`. This keeps the
   fixture independent of the code under test.
2. **Real transaction staging.** The crash-window tests stage the migration's
   actual multi-material journal transaction
   (`migrationJournalTransaction` recomputes the exact writes via the
   installed pipeline's records-migration transform, matching what
   `applyStorageLayoutMigration` itself produces) through the real
   `prepareJournalTransaction` primitive.
3. **Two genuine crash windows.** One test rewinds the manifest to `prepared`
   (crash before the journal's `staged-fsynced` transition); the other
   manually completes only the first promoted material (`events.jsonl`),
   leaving `records.jsonl`/`checkpoint.json` unpromoted and the manifest at
   `staged-fsynced` (crash after that transition — the exact window that
   exposed the data-loss defect). Neither test mocks `migration.ts` or
   `journal.ts`.
4. **Recovery assertions.** Both drive the real
   `migrateOperatingStorageLayoutOnOpen` entry point and assert full recovery:
   every pre-migration record digest re-reads successfully
   (`readEveryRecord`), no journal is left stuck
   (`recoverOperatingTransactions` returns `[]` on the next call), and the
   committed view is verified via `assertCommittedOperatingView`.
5. **Digest/event preservation and byte-exact rollback** are checked
   separately in the same file: post-migration `writeCheckpoint`/`replay`
   reproduce the exact pre-migration `eventHead`/`stateHash`/`recordDigests`,
   and a full-tree byte snapshot taken before migration is compared
   file-for-file, byte-for-byte, against the tree `rollbackStorageLayoutMigration`
   produces.
6. **Idempotence.** A second migration call and a second
   `migrateOperatingStorageLayoutOnOpen` call are both asserted as no-ops.

This is the strongest form of reproduction available short of an actual
process kill, and it is what surfaced the genuine defect documented in
`implementation.md` under T-001 — the crash-injection tests were not merely
regression coverage added after the fact; they found a real bug before this
feature shipped.
