# User Stories — Operating Board Agentic Engine

Source: `.planr/specs/SPEC-001-operating-board-agentic-engine/stories/US-*.md`.
All ten stories are `type: "Tech"` (backend engine work, no UI), each grounding

## US-001 — Automatic v1.3 storage-layout migration

**As** the Operating Board engine, **I want** any mutating `operate` command
that opens an old-layout project to migrate it journal-safely to the v1.3
layout, **so that** every project reaches the new on-disk shape automatically,
losslessly, and reversibly.

Acceptance outcome: a genuine old-layout project auto-migrates on the next
mutating command with every record digest and event preserved (verified by
checkpoint revalidation); `operate migrate rollback` restores the prior layout
byte-exact; a crash injected mid-migration recovers cleanly on the next
invocation; new projects initialize directly into v1.3 with no migration step;
every lens's `board/<role>.md` renders, including an explicit `not_evaluated`
status rather than an omission. Grounds FR5. No dependencies — dispatches in
parallel with US-002.

## US-002 — Live evidence index and digest-bound mission packets

**As** the Operating Board engine, **I want** to build a compact evidence
index (identity and signals, no file bodies) and a mission packet sourced from
live cycle state, **so that** each dispatched lens gets a single-digit-KiB
briefing instead of a pre-loaded content dump, and oversized construction
fails closed before dispatch.

Acceptance outcome: every index item carries path/revision/hash/classification/
freshness/sensitivity/signals with a content-scan test proving no body bytes
leak in; the pinned revision matches identically across the cycle manifest,
index, and every packet; a packet's charter/goals/prior-cycle/open-items/status
payload matches live project state exactly; a role whose packet would exceed
its budget fails closed with `E_OPERATE_MISSION_PACKET_BUDGET` naming that
role; every role's packet on the bundled demo project meets its budget.
Grounds FR1. No dependency on US-001 (disjoint file footprint).

## US-003 — Bounded, mode-aware native advisor dispatch

**As** the Operating Board engine, **I want** to dispatch native lenses with
exactly the granted read-only, path-confined, ceiling-narrowed tool set —
fanning out in parallel where supported, falling back where it can't be
enforced, and honoring a registry default plus a per-project override, **so
that** advisory lenses can investigate real files without ever writing,
executing, reaching the network, reading the environment, or escaping their
roots, while old-style pack-mode projects keep running unmodified.

Acceptance outcome: a new honeytoken suite proves all six refused channels
(write/exec/network/env/root-escape/above-ceiling-read) while an in-root,
at-or-below-ceiling read succeeds; the pre-existing pack-path honeytoken suite
passes unmodified in the same run; parallel and sequential dispatch reduce to
the same result set; adapters that cannot enforce the isolation boundary
route to the structured-provider path with the reconciliation recorded
explicitly; a mixed-mode cycle via `dispatchModeOverrides` completes with
byte-identical reduced events across dispatch order; projects with no
overrides and no role moved to the new mode run exactly as before. Grounds
FR2 and FR4's dispatch mechanics. Depends on US-002 (T-002) — sequenced, not
raced, on the shared dispatch call site.

## US-004 — Citation resolution as the audit mechanism

**As** the Operating Board engine, **I want** to resolve every citation a
native lens returns (repo path+range, git revision, or planr artifact ID)
against the cycle's pinned revision, snapshot it through redaction and
secret-scan, and reject unresolvable citations fail-closed into a gap, **so
that** auditability is verified after the fact instead of trusted from a
pre-loaded dump.

Acceptance outcome: a valid citation snapshots byte-faithfully with the
finding recording the resulting evidence ID; fabricated path, wrong line
range, and moved revision each reject with a distinct, correct reason and open
exactly one gap; a planr artifact citation resolves via an engine-computed
existence fact and snapshots through the same redaction path; a citation into
dirty, uncommitted content is named distinctly from fabricated-path; a secret
in cited content is redacted and never persists raw; a proposal with any
unresolvable citation never reaches consolidation. Grounds FR3. Depends on
US-003 (T-003) — a genuine output-contract dependency (citation fields live on
the dispatch output).

## US-005 — Quick-task routing for small, bounded findings

**As** an Operating Board operator, **I want** an accepted small, bounded
finding to route to a real quick task through the same journal, accept≠apply,
digest-preview, and byte-exact-rollback machinery every other route already
uses, **so that** small implementation work doesn't have to be inflated into a
full spec just to get a route target.

Acceptance outcome: a finding classified as small, bounded implementation work
produces a `create-quick-task` route; applying it (with its preview digest
confirmed) creates a real `.planr/quick/QUICK-NNN-{slug}.md` file through the
write-ahead journal with provenance, byte-exact to the preview; rolling it
back removes the file and restores state byte-exact; the existing route kinds
(spec, instrumentation-spec, decision, cycle-artifact) are unaffected; no
route, including the new one, ever invokes SHIP. Grounds FR6. Depends on
US-004 (T-004) — routes are created from citation-resolved findings.

## US-006 — Offline, self-contained decision-brief rendering

**As** a non-technical decision owner, **I want** `operate brief` /
`operate decisions show` to render a self-contained, offline artifact showing
the question, the cited evidence, the options, and what the decision blocks,
**so that** I can review and decide without a terminal, without the artifact
phoning home, and without my sensitivity ceiling being exceeded.

Acceptance outcome: a brief renders and is fully readable under an
opaque-origin sandbox with zero network requests; `operate decisions show`
displays the question, cited evidence, options, and what the decision blocks;
nothing publishes automatically — sharing requires the operator to explicitly
invoke the existing share flow; evidence above the configured sensitivity
ceiling never appears in rendered content. Grounds FR7. Depends on US-004
(T-004) — the brief renders citation-resolved snapshots, not raw content.

## US-007 — Cadence state and the never-acts guarantee

**As** an Operating Board operator, **I want** `operate status` to persist
`lastRunAt` and surface a real `nextDueAt` for weekly/monthly cadence (null
for manual), computed by a pure calculator with an injected clock, **so
that** cadence is a real, testable contract instead of a label, while a
cadence-triggered run still only ever stops at `reviewable`.

Acceptance outcome: weekly and monthly cadence report the calculator's correct
due date under an injected clock; manual cadence reports `nextDueAt: null`;
`lastRunAt` persists across process invocations and a subsequent `status`
call reflects it without re-running a cycle; an explicit, named test proves a
cadence-triggered run reaching `reviewable` never accepts a finding, applies a
route, or invokes PLAN/SHIP — not inferred from the absence of a call. Grounds
FR8. Depends on US-001 (T-001) and US-003 (T-003) — sequenced to avoid racing
shared facade/config files.

## US-008 — Skill-first, zero-adapter-command cycle

**As** a user running the Operating Board through a skill/plugin, **I want**
a full cycle — inspect → init → run → native lens dispatch → record →
finalize → chair → review — to complete without ever typing an adapter
lifecycle command myself, **so that** the CLI remains the authoritative,
scriptable state machine while the skill drives the whole interaction
invisibly.

Acceptance outcome: a scripted run reaches `reviewable` from a bare,
uninitialized project with zero user-typed adapter lifecycle commands in the
transcript; every JSON action's output shape matches what the skill path
expects at each step; adapters that cannot enforce native dispatch fall back
to the structured-provider path exactly as US-003 defines. This is primarily
verification of already-built pieces (US-002 through US-005) rather than new
behavior. Grounds FR9. Depends on US-003, US-004, and US-005.

exists upstream. Grounds FR10. Depends on US-001, US-003, and US-005.
